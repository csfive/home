# bash 编程与脚本

Shell 本身是一门编程语言。每条命令都有返回码，0 表示成功，非 0 表示失败，`$?` 保存上一条命令的返回码。`&&` 和 `||` 根据返回码短路，所以 `mkdir /tmp/x && cd /tmp/x` 只在建目录成功后才切换。`if` 和 `while` 判断的也是返回码，不是布尔值。

`test` 是最常用的条件命令，`[` 是它的另一种写法，所以 `[ -f file ]` 里方括号两边必须有空格。bash 另外提供了 `[[ ]]`，它支持 `&&`、`||` 和 `=~` 正则匹配，也不会因为变量为空而把语法拆坏，写 bash 脚本时优先用它。字符串比较用 `=`，数值比较用 `-eq`、`-lt` 这些，混用会得到意料之外的结果；算术运算可以写成 `(( n++ ))` 或 `$(( n + 1 ))`。

循环有两种常见形态：`for f in *.txt; do ...; done` 遍历展开后的文件，`while read -r line; do ...; done < file` 逐行读文件。`-r` 让反斜杠不被解释，读路径时几乎总是要加。`read -r -a arr <<< "$line"` 可以直接把一行拆进数组。

位置参数是脚本的入参：`$0` 是脚本名，`$1` 到 `$9` 是前九个参数，`$#` 是数量，`$@` 是全部参数。`"$@"` 展开成多个独立的词，保留每个参数里的空格；不加引号的 `$@` 会被再次切词。参数超过九个时用 `${10}`，或者 `shift` 逐个消费。

脚本的第一行通常是 shebang：`#!/usr/bin/env bash` 告诉内核用哪个解释器执行这个文件，`/usr/bin/env` 会去 `$PATH` 里找 `bash`。脚本需要可执行位才能直接运行，`chmod +x script.sh` 之后 `./script.sh` 才有效；不加 `./` 而直接写 `script.sh`，Shell 会去 `$PATH` 里找，当前目录通常不在其中。权限位里 `r` 是读、`w` 是写、`x` 是执行，`755` 表示所有者可读写执行、其他人可读可执行。

`set -euo pipefail` 是脚本的常用开头：`-e` 让任意命令失败时退出，`-u` 让引用未定义变量时退出，`-o pipefail` 让管道里任何一段失败都算失败。`set -e` 不是万能的，出现在 `if` 条件、`&&` 左值和 `!` 后面的命令不会触发退出，跨进度的错误仍然要自己检查。`set -x` 打印每条命令展开后的样子，是排错的第一手段。

后台任务用 `&` 启动，`$!` 拿到它的 PID，`kill` 用来结束它。函数用 `name() { ...; }` 定义，函数里的变量默认是全局的，要局部变量就写 `local`。

一个典型的脚本是这样反复跑测试直到失败，并只保留失败那一次的日志：

```bash
#!/usr/bin/env bash
set -euo pipefail

log="run-$(date +%s).log"
while cargo test my_test > "$log" 2>&1; do
  echo "passed"
done

tail -n 20 "$log"
```

写复杂脚本时，`shellcheck` 能指出大部分引号和返回码问题。脚本超过一百行、开始需要数据结构和错误处理时，通常应该改用 Python 之类的语言，而不是继续和 bash 的边界行为搏斗。
