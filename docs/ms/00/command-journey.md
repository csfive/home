# 一条命令的旅程

一行命令从回车到执行，要经过好几步，而且顺序是固定的：花括号展开、波浪号展开、参数与命令替换、切词、文件名展开。理解这个顺序，很多“为什么引号没保住空格”的问题就自然有答案了。

第一步是切词。空格和制表符把行拆成词，连续空白算一个分隔符。不过切词发生在展开之后，而不是一开始：Shell 先按语法找出命令和参数的边界，再对未加引号的部分做词分割。`IFS` 决定分隔符集合，默认是空格、制表符和换行。

引号在这一步里起保护作用。单引号里的内容完全字面，连 `$` 都不展开；双引号保留变量和命令替换，但阻止切词；反斜杠转义后面那一个字符；`$'...'` 是 ANSI-C 写法，可以写 `\n`、`\t` 这样的转义序列。需要字面量 `$`、`!` 和换行时，这三种写法各有用途：

```bash
echo 'cost: $5'
echo "cost: $HOME"
printf '%s\n' $'line1\nline2'
```

引号处理完，变量才开始展开。`$HOME`、`${HOME}` 都是取值，花括号用来划清变量名的边界，`${HOME}dir` 不会去找一个叫 `HOMEdir` 的变量。`export` 把变量放进环境，子进程才能继承；没有 `export` 的变量只属于当前 Shell。命令替换 `$(...)` 会先执行里面的命令，用它的标准输出替换当前位置，末尾的换行会被去掉。

展开的结果还会再次切词。`files="a b"; rm $files` 会删掉两个文件，因为展开后的空格又变成了分隔符；写成 `rm "$files"` 才是一个参数。这是 Shell 里最常见的一类 bug。`"$@"` 是同一个道理的正面例子：它展开成多个独立的词，每个参数里的空格都被保留。

接下来是文件名展开，也就是 glob。`*` 匹配任意长度的字符，`?` 匹配一个字符，`[]` 匹配字符集合，`**` 在开启 globstar 后递归匹配。glob 不匹配以点开头的隐藏文件，`.` 和 `..` 也不参与。没有文件匹配时，bash 默认把模式原样保留，程序真的会收到一个叫 `*.py` 的参数；`nullglob` 会把它变成空，`failglob` 则直接报错。花括号展开 `{a,b}` 发生在 glob 之前，它纯粹是文本替换，不需要文件存在。

词都准备好了，Shell 沿着 `$PATH` 找程序。`$PATH` 是用冒号分隔的目录列表，从左到右查找，第一个命中的生效，所以路径顺序就是优先级。`which -a` 和 `type -a` 能看到所有候选；`type -a` 还会告诉你某个名字是别名、函数、内建命令还是外部程序。bash 会把查到的路径缓存起来，`hash -r` 清掉缓存，换过解释器或装过新版本后很有用。`command -v` 是 POSIX 的写法，脚本里比 `which` 可靠。

找到之后，Shell 先 `fork` 出子进程，子进程再 `exec` 成目标程序，父进程用 `wait` 等它结束。内建命令不走这条路：`cd`、`export`、`umask` 必须由 Shell 自己执行，因为子进程改不了父进程的工作目录和环境。

想看每一步展开后的真实结果，用 `set -x` 打开追踪，或者把命令前面加上 `echo` 做干跑。`set -x` 输出的是展开之后的命令，比自己脑补快得多。
