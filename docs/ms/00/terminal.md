# 终端与 Shell

终端和 Shell 是两样东西。终端负责显示字符、接收按键；Shell 是跑在终端里的一个普通程序，负责解释你输入的那一行。屏幕上出现的文字，是终端把收到的字节画出来；你敲下的按键，是终端把它们交给 Shell。

终端的历史比图形界面长得多。最早的终端是 ASR-33 这样的电传打字机，一台机器上接着一条线，线的末端就是计算机。Teletypewriter 被缩写成 TTY，所以今天终端设备还叫 `tty`，`tty` 命令会打印当前终端的设备路径。VT100 是另一条支线：它不再靠机械打字，而是用一组控制序列来移动光标、改变颜色。今天的终端模拟器仍然解释同一套序列，`$TERM` 告诉程序自己模拟的是哪一台，terminfo 数据库描述这台终端支持哪些能力。

`$TERM` 只是一个名字，不是能力本身。`xterm-256color` 和 `screen-256color` 都支持颜色，但转义序列的细节不同；名字写错时，程序要么不敢用颜色，要么输出一堆乱码。`tput colors` 会去查 terminfo，告诉你当前终端支持多少色。同理，`tput setaf 2` 生成的是“把前景色设为绿色”的转义序列，而不是写死 `\e[32m`。

Shell 的工作是一个循环：打印提示符，读入一行，切词、展开、找到程序、启动它、等它结束、记下返回码，然后回到提示符。提示符通常由 `$PS1` 决定，默认形态是 `user@host:cwd$`，其中 `$` 表示你不是 root。`root` 的提示符一般以 `#` 结尾，这是视觉上的提醒，不是权限机制的边界。

命令行最终交给程序的是一个字符串数组，习惯上叫 `argv`。执行 `echo hello` 时，Shell 找到 `echo` 这个程序，把 `argv[0]` 设为 `echo`、`argv[1]` 设为 `hello`，剩下的解释工作归程序自己。Shell 并不理解 `hello` 是什么意思，它只负责把词切开。也正因为这样，同一个 `-l` 在 `ls` 里是长格式，在别的程序里可能是完全不同的意思。

常见的 Shell 不止 bash。zsh 在兼容 bash 语法的同时补了自动补全和主题，fish 干脆换了一套更友好的语法，POSIX `sh` 则是最小公共集。`echo $SHELL` 显示的是登录 Shell，不一定是当前正在用的那个；想看当前进程，用 `ps -p $$` 或 `echo $0`。登录 Shell 由 `/etc/shells` 里的路径决定，`chsh -s /bin/zsh` 可以改，但改完要重新登录才生效。

Shell 分登录和非登录、交互和非交互两种维度，启动时读的配置文件也不同。这个区别解释了很多“为什么我的配置在脚本里不生效”的问题，后面讲 dotfile 时会再展开。
