# 终端与 Shell

终端负责显示和输入，Shell 负责解释命令。两者经常被混为一谈，但一个是设备，一个是进程。

## 分工

|      | 终端                       | Shell              |
| ---- | -------------------------- | ------------------ |
| 角色 | 显示字符、接收按键         | 解释命令、启动进程 |
| 例子 | iTerm2、Alacritty、Ghostty | bash、zsh、fish    |
| 边界 | 窗口关掉就没了             | 会话里可以有很多个 |

分清这一点，后面两条线就不会混：TTY 的历史属于终端，路径查找和进程启动属于 Shell。

## 从 TTY 到模拟器

- ASR-33 电传打字机，Teletype 缩写成 TTY
- `tty` 打印当前终端设备路径
- VT100 用控制序列移动光标、改变颜色
- 终端模拟器解释同一套 ANSI 序列

```bash
tty
echo $TERM
tput colors
```

`$TERM` 只是能力名，不是能力本身。terminfo 数据库描述它支持哪些序列，名字写错时程序要么不敢用颜色，要么输出乱码。

## Shell 的循环

1. 打印提示符，通常由 `$PS1` 决定
2. 读入一行
3. 切词、展开
4. 沿 `$PATH` 查找程序
5. `fork` + `exec`，父进程 `wait`
6. 记录返回码，回到 1

## 提示符与路径

提示符由 `$PS1` 渲染，`user@host:path$` 里的 `~` 代表 home，末尾是 `$` 表示普通用户，root 显示 `#`。

以 `/` 开头的是绝对路径；相对路径从当前目录开始，逐段解析。`.` 是当前目录，`..` 是上一级，根目录的 `..` 仍然是根，所以 `cd ..` 在那里不会报错。

```bash
cd /usr/bin      # 绝对路径
cd bin           # 相对路径，必须在当前目录下有 bin
cd ~             # 回到 home
cd ../../project # 逐级向上再进入
```

输入前几个字母按 `Tab` 补全路径，有多个候选时连按两次会全部列出。`zoxide` 记住访问过的目录，`z proj` 直接跳过去，不必逐级 `cd`。

## argv

`echo hello` 交给程序的是 `["echo", "hello"]`。Shell 只负责切词，`hello` 是什么意思由程序解释。

| 变量      | 作用域       | 含义       |
| --------- | ------------ | ---------- |
| `$0`      | 脚本 / Shell | 程序名     |
| `$1`…`$9` | 脚本         | 前九个参数 |
| `$#`      | 脚本         | 参数个数   |
| `$@`      | 脚本         | 全部参数   |

这些变量只在脚本或函数里有实际内容；交互式 Shell 里通常为空。

## 不同 Shell

| Shell | 特点                    |
| ----- | ----------------------- |
| bash  | 默认选择，POSIX 的超集  |
| zsh   | 补全、主题、插件更丰富  |
| fish  | 语法更友好，不兼容 bash |
| sh    | 最小公共集，脚本可移植  |

`echo $SHELL` 显示登录 Shell，`ps -p $$` 才是当前进程。改默认 Shell 用 `chsh -s /bin/zsh`，重新登录后生效。
