# 容易混淆的问题

**`$SHELL` 与 `$0` 不是一回事。** `$SHELL` 是登录时用的 Shell，来自账号配置；`$0` 是当前这个 Shell 进程的名字。想看真实进程，用 `ps -p $$`。

**`$TERM` 与终端能力。** `$TERM` 只是一个名字，比如 `xterm-256color`，真正的能力表在 terminfo 里。名字写错，程序要么不敢用颜色，要么输出一堆乱码。

**终端里跑非 Shell 程序。** `vim`、`python`、`less` 都是普通进程，只是它们关闭了行规程的回显和行编辑，自己处理按键，退出时再把终端恢复原状。

**没有终端的环境。** 脚本、CI、`ssh host cmd` 里没有 tty，`isatty` 为假，行缓冲变成块缓冲，需要交互的程序会直接失败。`ssh -t` 可以强制分配一个伪终端。

**`Ctrl-C` 的完整链路。** 按键先到终端驱动，驱动给前台进程组发 `SIGINT`，进程自己决定退出还是捕获。Shell 只负责作业控制，并不亲手发这个信号。

**`if` 与 `[`。** `[` 是一条命令，不是语法，所以方括号两侧要有空格，末尾要有 `]`。`[[ ]]` 是 bash 的语法结构，规则不同，支持模式匹配和正则。

**`$?` 与 `$!`。** `$?` 是上一条命令的返回码，`$!` 是最后一个后台进程的 PID。

**`./script.sh` 与 `PATH`。** 当前目录默认不在 `PATH` 里，直接写 `script.sh` 会找不到；`./script.sh` 明确指定路径，再配合 shebang 和可执行位才能运行。
