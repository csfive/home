# 命令行环境

[课后练习答案](https://github.com/csfive/missing-semester/tree/main/01-command-line-environment '非官方，仅供参考')

## 参数与 flag

命令行程序收到的永远只是一个字符串数组。执行 `ls -l folder/` 时，程序看到的是 `["ls", "-l", "folder/"]`，它得自己决定 `-l` 是什么意思、`folder/` 是不是路径。这种约定没有语言层面的强制，但几乎所有人都遵守：短选项一个减号加一个字母，长选项两个减号加一个单词，两者通常等价，`ls -a` 和 `ls --all` 做同一件事。

短选项可以合并，`ls -l -a` 与 `ls -la` 相同；选项顺序一般无关，`ls -la` 与 `ls -al` 结果一样；可变数量的文件参数可以并排写，`mkdir src docs` 等价于两次 `mkdir`。`--help`、`--version`、`--verbose` 是三个几乎成了标准的名字。

减号开头的参数会和一个叫 `-myfile` 的文件名冲突，`--` 用来划清界线：它之后的内容一律当位置参数，不再当选项解析。`touch -- -myfile` 可以创建这个文件，删的时候同样要 `rm -- -myfile`，否则 `rm` 会以为 `-m` 是选项。

在脚本里，这些参数通过位置变量访问：`$1` 到 `$9` 是前九个，`$#` 是数量，`$@` 是全部，`$0` 是脚本名。`"$@"` 加上引号会展开成多个独立的词，每个参数里的空格都被保留；不加引号则会重新切词。

还有一层容易忽略的机制：文件通配符在程序启动前就已经展开。你敲 `rm *.py` 时，`rm` 收到的是展开后的文件名列表，而不是字符串 `*.py`。所以程序无法分辨某个参数是用户手写的还是 Shell 展开的，这也是为什么参数里出现空格时，引号必须一路带到程序那一层。

## 流与管道

每个程序都有三个默认的流：标准输入、标准输出、标准错误。管道 `|` 把前一个程序的标准输出接到后一个程序的标准输入，两个程序同时运行，而不是先跑完一个再跑下一个。用一个带延迟的例子能看清楚这一点：

```bash
(sleep 15 && cat numbers.txt) | grep -E '^\d$' | sort | uniq
```

执行后立刻看 `ps`，`grep`、`sort`、`uniq` 已经在运行，只有 `cat` 还在等 `sleep` 结束。Shell 先把所有进程启动起来，再把它们的流接好，数据流到哪一步，哪一步才开始干活。

很多程序接受 `-` 作为文件名，表示从标准输入读。`echo hello | grep hello` 和 `echo hello | grep hello -` 等价。标准错误是另一条输出流，专门放警告和错误，默认不进管道，所以 `ls /nonexistent | grep pattern` 的报错仍然会出现在屏幕上。

重定向就是把某个流改到别处：`>` 覆盖写文件，`>>` 追加，`2>` 改标准错误，`&>` 同时改 1 和 2，`<` 从文件读，`/dev/null` 丢弃。`2>&1` 要放在 `>` 之后，先让 stdout 指向文件，再让 stderr 跟着 stdout 走，顺序反过来错误就会留在终端。

[`fzf`](https://github.com/junegunn/fzf) 是一个把管道变成交互界面的工具：它从标准输入读行，让你边打字边过滤，最后把选中的行写回标准输出。`ls | fzf` 用来选文件，`history | fzf` 用来翻历史；第 8 节里还会看到它接管 `Ctrl-R` 的用法。

## 变量与环境

Shell 变量都是字符串，赋值时等号两边不能有空格：`foo=bar` 是赋值，`foo = bar` 会被当成执行 `foo`，参数是 `=` 和 `bar`。空格在 Shell 里的本职工作是切词，所以它出现在哪里都不是小事。

单引号和双引号不能互换。单引号里的内容是字面量，`$foo` 不会展开；双引号里会展开变量、命令替换和反斜杠转义。`echo '$foo'` 打印 `$foo`，`echo "$foo"` 打印变量的值。

命令替换 `$(...)` 用命令的标准输出替换当前位置，末尾换行会被去掉，中间换行保留，所以 `files=$(ls)` 里的每一项仍然各占一行。进程替换 `<(...)` 更进一步：它执行命令，把输出放进一个临时文件，再把文件名替换进来，适合那些只接受文件参数、不读标准输入的程序，比如 `diff <(ls src) <(ls docs)`。

环境变量是传给子进程的那部分变量。`printenv` 列出当前环境，`export` 把变量加进环境，`unset` 删除。只给一条命令设置环境时，把赋值写在命令前面：`TZ=Asia/Tokyo date` 只影响这一条命令，执行完 `$TZ` 仍然是空的。环境变量习惯用全大写，这只是约定，用来和普通的 Shell 变量区分。

`$HOME`、`$PATH` 这类变量体现了约定式配置的价值：程序不需要一个 `--home` 参数，读环境就能知道该去哪。`source file` 和 `.` 则在当前 Shell 里执行脚本，所以里面的变量和函数会留下来；`./file` 会开一个子进程，改动出不来。子 Shell 也是同样的道理，`(cd /tmp; pwd)` 不会改变外层的工作目录。

## 返回码与条件

返回码是程序退出的状态，0 表示成功，非 0 表示失败。Shell 脚本默认返回 0，用 `exit NUM` 指定其他值，`$?` 读取上一条命令的返回码。

`&&` 和 `||` 根据返回码短路：`grep -q pattern file && echo found` 只在找到时打印，`|| echo missing` 则相反。`if` 和 `while` 判断的也是命令的返回码，`while read line; do ...; done < file` 之所以能读完整个文件，是因为 `read` 在遇到 EOF 时返回非 0。

返回码只有一个字节，范围是 0 到 255。`exit 256` 实际会变成 0，`kill -9` 之后的 137 是 128 加 9。写脚本时如果拿返回码当错误类型用，要记得这个上限。

## 信号与作业控制

信号是一种软件中断，进程收到后可以退出、暂停，也可以捕获后自行处理。`Ctrl-C` 对应 `SIGINT`，`Ctrl-\` 对应 `SIGQUIT`，`Ctrl-Z` 对应 `SIGTSTP`。很多人以为是 Shell 在发信号，实际上是终端驱动把信号发给当前的前台进程组；Shell 只是负责作业控制，记录谁在前台、谁被挂起。

`SIGTERM` 是通用的终止请求，`kill -TERM PID` 发送它，`kill -l` 列出所有信号。`SIGKILL` 是例外，它不能被捕获，进程一定会死，代价是来不及清理，可能留下孤儿子进程。`SIGHUP` 在终端关闭时发出，这就是后台任务跟着终端一起消失的原因。

作业可以用 job spec 引用：`jobs` 列出当前终端的作业，`%1` 是第一个，`kill %1` 结束它，`$!` 是最后一个后台进程的 PID。`&` 让命令在后台启动，`fg` 把它调回前台，`bg` 让挂起的作业继续在后台运行。

进程的生命周期不只属于当前 Shell。`nohup` 让程序忽略 `SIGHUP`，`disown` 把已经启动的作业从作业表里移除，两者都不能让进程在终端关闭后继续读终端；`tmux` 从根上解决这个问题。脚本里可以用 `trap cleanup EXIT` 在退出时执行清理，也可以捕获 `SIGINT`、`SIGTERM` 做优雅退出。

跨 Shell 等待进程时，`wait` 只对自己启动的子进程有效；要等一个不认识的 PID，可以用 `kill -0` 探活，它不发信号，只在进程不存在时返回非 0。

## 远程机器

`ssh user@host` 打开一个远端 Shell，连接本身是加密的。它也可以只跑一条命令：`ssh host ls` 把远端 `ls` 的输出带回来，`ssh host 'ls | wc -l'` 则在远端执行整条管道。区别在于引号归谁解释：不带引号时，本地 Shell 先展开并切词，再交给远端；带引号时，整串原样送过去。需要本地变量先展开时，用双引号；需要远端展开时，用单引号。

密码登录不如密钥。`ssh-keygen -a 100 -t ed25519` 生成一对密钥，私钥留在本地，公钥用 `ssh-copy-id` 追加到远端的 `~/.ssh/authorized_keys`。服务端只认公钥，客户端用私钥证明自己持有对应的秘密，全程不传私钥。私钥文件权限必须是 600，目录是 700，否则 `ssh` 会拒绝使用；`known_hosts` 记录第一次连接时服务端的指纹，换机器或重装后会报警。

`~/.ssh/config` 给主机起别名并预设参数：

```sshconfig
Host vm
    User alice
    HostName 172.16.174.141
    Port 2222
    IdentityFile ~/.ssh/id_ed25519
```

`Host` 支持通配，`Host *.mit.edu` 可以给一整批机器设默认值。`scp` 和 `rsync` 都读这份配置。`rsync` 比 `scp` 多做了增量判断，还支持 `--partial` 续传；源路径末尾有没有 `/` 含义不同，`src/` 复制目录内容，`src` 复制目录本身。

需要转发端口时，`LocalForward 9999 localhost:8888` 把本地端口接到远端服务上，配合 `ssh -N -f` 可以在后台只做转发、不开 Shell。[`mosh`](https://mosh.org/) 是 SSH 的替代品，网络切换或休眠后能恢复会话，适合移动环境。

## 终端复用

`tmux` 把多个 Shell 放进一个终端窗口，分为三层：session 是一次独立的工作区，window 相当于标签页，pane 是窗口里的分屏。启动 `tmux` 会新建一个 session，`tmux new -s name` 给它起名，`tmux ls` 列出所有 session，`tmux a -t name` 重新接上。

所有快捷键都带前缀 `Ctrl-b`，按完松开再按下一个键。`<C-b> d` 分离当前 session，进程继续在后台运行；`<C-b> c` 新建 window，`<C-b> N` 跳到第 N 个，`<C-b> w` 列出 window；`<C-b> %` 垂直分屏，`<C-b> "` 水平分屏，方向键切换 pane，`<C-b> z` 把当前 pane 放大，`<C-b> [` 进入滚屏和复制模式。

它最大的价值在远端：SSH 断开、网络抖动、笔记本合盖，session 都还在服务器上，重新 `tmux a` 就能接着用，不需要 `nohup` 那一套。

## Shell 定制

以点开头的文件默认不显示，配置就藏在这些 dotfile 里：`~/.bashrc`、`~/.gitconfig`、`~/.vimrc`、`~/.ssh/config`、`~/.tmux.conf`。Shell 启动时读哪个文件，取决于它是登录 Shell 还是交互 Shell：登录 Shell 读 `~/.bash_profile` 或 `~/.profile`，交互非登录 Shell 读 `~/.bashrc`。很多系统在 profile 里显式 `source ~/.bashrc`，把两条路径接上。

最常见的改动是往 `$PATH` 里加目录：`export PATH="$PATH:$HOME/.local/bin"`。重复执行会累积重复项，路径顺序决定优先级，排在前面的一直赢。

`alias` 给命令起短名，`alias ll="ls -lh"` 之后 `ll` 就等价于那串命令；`alias ll` 查看定义，`\ls` 绕过别名，`unalias` 删除。别名只是文本替换，不能在中间插参数，需要逻辑时写函数。`history` 记录命令，`Ctrl-R` 反向搜索，装了 fzf 之后 `Ctrl-R` 会变成模糊搜索整个历史。

dotfile 应该有自己的仓库，再用符号链接放回 home 目录。这样换机器只需要 clone 一次、跑一遍链接脚本，改动也有版本记录。安装脚本要小心 `curl ... | bash` 这种写法，它直接执行没看过的代码；先下载、读一遍、再执行更稳妥。

工具本身用包管理器装：macOS 是 Homebrew，Debian/Ubuntu 是 `apt`，Fedora 是 `dnf`，Arch 是 `pacman`。装完可以试试 `ripgrep` 和 `fd`，它们分别是 `grep` 和 `find` 的现代版本；`tldr` 给出命令的常用例子，command-not-found.com 则告诉你某个命令该用哪个包安装。

zsh 生态里有 oh-my-zsh、prezto 这类框架，也有语法高亮、自动建议、补全增强这些单独插件。框架省事，但会拖慢启动；只装真正用到的插件通常更快，也更好控制。`$PS1` 控制提示符，补全和语法高亮则决定了日常输入的顺手程度。

最后是终端模拟器本身：字体、配色、滚屏行数、快捷键都值得调一次。Alacritty、Ghostty 这类新终端用 GPU 渲染，`$TERM` 告诉里面的程序支持哪些能力。

## AI 在命令行里

最轻的用法是让模型生成命令：`llm cmd "find all python files modified in the last week"` 直接给出 `find . -name "*.py" -mtime -7`。更实用的是把模型接进管道：面对格式不统一的文本，正则写起来很痛苦，但 `llm "$INSTRUCTIONS" < users.txt` 可以按自然语言要求抽取字段，输出继续交给后面的命令处理。

再进一步是 AI Shell 和 agent 工具：它们接受英文描述，自己决定调用哪些命令、改哪些文件，适合多步骤任务。用得越深，越需要把上面这些基础概念弄清楚，否则很难判断它到底做了什么。

## 容易混淆的问题

**`source` 与 `./script.sh`**。前者在当前 Shell 里执行，变量和函数会留下；后者启动子进程，执行完就没了。改 `PATH`、定义函数要用 `source`。

**`$?` 与 `$!`**。`$?` 是上一条命令的返回码，`$!` 是最后一个后台进程的 PID。两者都和进程有关，但一个是状态，一个是编号。

**`kill %1` 与 `kill PID`**。`%1` 是当前 Shell 的作业编号，只在本终端有效；PID 是系统级编号，跨终端可用。`kill -l` 能查信号名。

**`Ctrl-C` 与 `Ctrl-Z`**。前者发 `SIGINT`，默认终止进程；后者发 `SIGTSTP`，只是挂起，可以用 `fg` 或 `bg` 恢复。

**`nohup`、`disown` 与 `tmux`**。`nohup` 让程序忽略挂断信号，`disown` 把作业从 Shell 的作业表摘掉，`tmux` 让程序跑在一个独立的会话里。前两者解决信号问题，后者解决会话问题。

**`ssh host cmd` 的引号归属**。不带引号，本地 Shell 先展开再发过去；带单引号，远端才展开。要传本地变量，用双引号；要让远端自己算，用单引号。

**`-` 是 stdin 还是文件名**。这是程序的约定，不是 Shell 的语法。大多数工具把单独的 `-` 当标准输入，但并非所有程序都这样。

**`--` 是参数还是终止符**。它本身不是参数，而是一条分界线：在它之后，所有减号开头的字符串都当普通参数。

**`alias` 与函数**。别名只做文本替换，不能接受中间参数；需要参数、条件或循环时，写函数。

**`$@` 加不加引号**。加引号时每个参数保持独立，不加引号会重新切词。遍历参数时几乎总是要 `"$@"`。

**信号是 shell 发的还是终端发的**。正常交互下，是终端驱动把 `SIGINT` 发给前台进程组，Shell 只记录作业状态。在脚本里用 `kill` 才是主动发信号。

**关闭终端为何杀掉后台任务**。终端关闭时内核给会话里的进程发 `SIGHUP`，后台任务默认没有忽略它，所以一起退出。
