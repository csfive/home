# 变量与环境

Shell 变量都是字符串，赋值时等号两边不能有空格：`foo=bar` 是赋值，`foo = bar` 会被当成执行 `foo`，参数是 `=` 和 `bar`。空格在 Shell 里的本职工作是切词，所以它出现在哪里都不是小事。

单引号和双引号不能互换。单引号里的内容是字面量，`$foo` 不会展开；双引号里会展开变量、命令替换和反斜杠转义。`echo '$foo'` 打印 `$foo`，`echo "$foo"` 打印变量的值。需要换行、制表符这类转义时用 `$'...'`，它是 ANSI-C 写法，和另外两种引号是并列关系。

命令替换 `$(...)` 用命令的标准输出替换当前位置，末尾换行会被去掉，中间换行保留，所以 `files=$(ls)` 里的每一项仍然各占一行。反引号是旧写法，不能嵌套，新代码一律用 `$()`。

进程替换 `<(...)` 更进一步：它执行命令，把输出放进一个临时文件，再把文件名替换进来，适合那些只接受文件参数、不读标准输入的程序。`diff <(ls src) <(ls docs)` 比较两个目录的文件名；`comm -12 <(sort a) <(sort b)` 求交集。写成 `=(...)` 则直接把临时文件名交出去，而不是通过 `/dev/fd`。

环境变量是传给子进程的那部分变量。`printenv` 列出当前环境，`export` 把变量加进环境，`unset` 删除。只给一条命令设置环境时，把赋值写在命令前面：`TZ=Asia/Tokyo date` 只影响这一条命令，执行完 `$TZ` 仍然是空的。`env -i` 可以清空环境再执行，用来复现“为什么换个环境就坏了”。

环境变量习惯用全大写，这只是约定，用来和普通的 Shell 变量区分。`$HOME`、`$PATH` 这类变量体现了约定式配置的价值：程序不需要一个 `--home` 参数，读环境就能知道该去哪。反过来，环境变量也是隐式依赖，排查问题时 `printenv | sort` 比翻代码更快。

`source file` 和 `.` 则在当前 Shell 里执行脚本，所以里面的变量和函数会留下来；`./file` 会开一个子进程，改动出不来。子 Shell 也是同样的道理，`(cd /tmp; pwd)` 不会改变外层的工作目录，`(export A=1)` 也不会污染父进程。

变量还有作用域和属性：函数里默认是全局变量，写 `local` 才局部；`readonly` 禁止修改；`declare -a` 声明数组；`export -f` 把函数导出给子 Shell。用不到时不要加，Shell 的隐式状态已经够多了。
