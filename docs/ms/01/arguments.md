# 参数与 flag

命令行程序收到的永远只是一个字符串数组。执行 `ls -l folder/` 时，程序看到的是 `["ls", "-l", "folder/"]`，它得自己决定 `-l` 是什么意思、`folder/` 是不是路径。这种约定没有语言层面的强制，但几乎所有人都遵守：短选项一个减号加一个字母，长选项两个减号加一个单词，两者通常等价，`ls -a` 和 `ls --all` 做同一件事。

短选项可以合并，`ls -l -a` 与 `ls -la` 相同；选项顺序一般无关，`ls -la` 与 `ls -al` 结果一样；可变数量的文件参数可以并排写，`mkdir src docs` 等价于两次 `mkdir`。`--help`、`--version`、`--verbose` 是三个几乎成了标准的名字。

减号开头的参数会和一个叫 `-myfile` 的文件名冲突，`--` 用来划清界线：它之后的内容一律当位置参数，不再当选项解析。`touch -- -myfile` 可以创建这个文件，删的时候同样要 `rm -- -myfile`，否则 `rm` 会以为 `-m` 是选项。写脚本时，`--` 是处理“用户输入可能以减号开头”的最简单办法。

还有一种约定是可变参数：同一个操作作用于多个文件，`rm a b c`、`mkdir src docs` 都是这个模式。它和 glob 结合才真正好用，`rm *.py` 由 Shell 展开成完整列表，程序只负责逐个处理。

在脚本里，这些参数通过位置变量访问：`$1` 到 `$9` 是前九个，`$#` 是数量，`$@` 是全部，`$0` 是脚本名。`"$@"` 加上引号会展开成多个独立的词，每个参数里的空格都被保留；不加引号则会重新切词。参数超过九个时写 `${10}`，或者用 `shift` 逐个消费。

```bash
while [[ $# -gt 0 ]]; do
  case "$1" in
    -v|--verbose) verbose=1; shift ;;
    *) files+=("$1"); shift ;;
  esac
done
```

需要更复杂的行为时，不要手写解析：Python 用 `argparse`，Go 用 `flag`，Rust 用 `clap`，它们在库层面保证长短选项、默认值、帮助文本和错误提示一致。

还有一层容易忽略的机制：文件通配符在程序启动前就已经展开。你敲 `rm *.py` 时，`rm` 收到的是展开后的文件名列表，而不是字符串 `*.py`。所以程序无法分辨某个参数是用户手写的还是 Shell 展开的，这也是为什么参数里出现空格时，引号必须一路带到程序那一层。

环境变量则是另一条传参通道：它不占 argv，子进程默认继承，适合放配置而不是数据。`NO_COLOR=1`、`LANG`、`EDITOR` 都是这个用法，细节放在「变量与环境」里。
