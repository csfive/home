## 终端与 Shell

终端是窗口，Shell 是窗口里运行的程序。终端负责显示与输入，Shell 负责解析命令、查找程序、执行并返回结果。

### 硬件终端

上世纪六七十年代，主机放在机房，操作台通过一条串口线与主机相连。VT100 和电传打字机（ASR-33）都属于这类设备。Terminal 的原意是「线路的末端」，指的正是链路的这一头。

这类设备没有处理器，也不执行程序，只完成两件事：把按键转换成字节写入串口，把主机返回的字节显示在屏幕上。全部计算都在机房的机器上完成。

电传打字机的英文是 Teletypewriter，缩写 TTY，这个名称保留到了今天。`tty` 命令显示当前终端设备，`ps` 输出的 `TTY` 列显示进程挂在哪个终端下。

### 终端模拟器

真实硬件终端已经很少使用。日常打开的「终端」是终端模拟器，一个普通 GUI 程序，在窗口里重现终端的行为。

输入侧多了鼠标和粘贴；输出侧除了字符，还多了颜色、光标、标签页、分屏、透明度和滚动缓冲。除此之外，它做的事情与当年的 VT100 相同：收发字节。

之所以称为模拟器，是因为 VT100 那套控制码成了通用约定，`\e[2J` 表示清屏，`\e[31m` 表示红色，后续终端都照着实现。模拟器实现的是协议，不是那台机器本身。

### Shell 的读入循环

Shell 是一个常驻进程，大部分时间在执行同一个循环：

```text
提示符 → 读一行 → 解析/展开 → 查找程序 → 执行 → 等待结束 → 提示符
```

最简的命令只有一个词，Shell 拿它去 `$PATH` 里找程序：

```bash
date
```

多个词的情况，第一个是程序名，其余按顺序成为参数。它们最终构成程序的 `argv` 数组，对应 C 的 `argc` / `argv`、Java 的 `String[] args` 和 Python 的 `sys.argv`。命令名一般不带 `.java`、`.py` 等扩展名，因为命令是已编译的可执行文件，或是开头用 `#!` 声明了解释器的脚本。

### 提示符的构成

```text
missing:~$
```

`missing` 是主机名，`~` 是当前目录（home 的简写），`$` 表示当前用户不是 root，root 的提示符通常以 `#` 结尾。常见配置会在前面加上用户名，拼成「用户@主机：路径」的形式。

## 一条命令的旅程

一行命令从按下 Enter 到程序运行，中间经过切词、引号处理、变量展开、文件名展开、程序查找和进程创建。前四步决定 `argv` 的内容，后两步决定这段 `argv` 交给谁执行。

### 切词

Shell 按空白切分整行，连续多个空格只相当于一个分隔符：

```bash
echo hello world      # hello world
echo "hello world"    # hello world
echo hello\ world     # hello world
echo hello     world  # hello world
```

四行输出完全相同。`echo` 用单个空格把参数拼回去，屏幕上看不出参数被切成了几段。换成按参数逐个处理的 `printf`，差别立刻出现：

```bash
printf '<%s>\n' hello world
# <hello>
# <world>

printf '<%s>\n' "hello world"
# <hello world>
```

### 引号

引号管两件事：保住中间的空白，决定里面的 `$`、反引号和反斜杠要不要展开。

```bash
echo '$HOME'        # $HOME
echo "$HOME"        # /home/you
name=world
echo "hello $name"  # hello world
echo 'hello $name'  # hello $name
```

| 写法     | 空白       | `$` 与命令替换 | 转义                                                    |
| -------- | ---------- | -------------- | ------------------------------------------------------- |
| `'...'`  | 保留       | 不展开         | 全部按字面                                              |
| `"..."`  | 保留       | 展开           | `\` 仍然生效                                            |
| `\`      | 转义后保留 | 不适用         | 只作用于后一个字符，`hello\ world` 里的空格不再是分隔符 |
| `$'...'` | 保留       | 不展开         | 支持 `\n`、`\t` 等 ANSI-C 转义                          |

引号本身不会进入 `argv`，它只是解析阶段的标记。引号没有闭合时，Shell 进入续行状态等待补全，按 `Ctrl-C` 可以取消这次输入。

### 变量与命令替换

```bash
name=world          # 等号两边不能有空格
echo "$name"
echo "${name}!"     # 花括号划清变量边界
echo "today: $(date +%F)"
```

`name=value` 定义 Shell 变量，`$name` 取值，`${name}` 在与其他字符拼接时边界更清晰。`$(命令)` 是命令替换：先执行命令，再把输出放回当前位置。旧写法使用反引号，不能嵌套，`$()` 没有这个限制。变量需要经过 `export` 才会成为环境变量并传给子进程。

变量展开之后如果外面没有引号，Shell 还会对结果再做一次切词和 glob 展开：

```bash
files='a.txt b c.txt'

printf '[%s]\n' "$files"
# [a.txt b c.txt]

printf '[%s]\n' $files
# [a.txt]
# [b]
# [c.txt]
```

| 写法       | 参数个数 | 每个参数              |
| ---------- | -------- | --------------------- |
| `"$files"` | 1        | `a.txt b c.txt`       |
| `$files`   | 3        | `a.txt`、`b`、`c.txt` |

`printf` 对每个参数重复一次格式字符串，因此第二种写法输出三行。加引号时，空格只是字符串中的一个字符，整个值作为单个参数传入；不加引号时，空格、Tab 和换行都被当作分隔符。

zsh 默认不执行 word splitting，`$files` 和 `"$files"` 都只产生一个参数，需要显式切分时写 `${=files}`。bash 里 `echo $files` 同样看不出区别，因为 `echo` 又把切开的参数拼了回去，只有 `printf` 这种按参数逐个处理的程序才会暴露个数差异。

变量默认加双引号。`$(ls)` 的输出以换行分隔，不加引号会被再切一次，而文件名本身带空格时，切开之后就没法拼回原样。

### 文件名展开

`*`、`?`、`[]` 是文件名的匹配模式。Shell 在调用程序之前把模式替换成匹配到的文件列表，这一步叫 glob，规范名称是 pathname expansion。程序收到的已经是文件名，不是 `*`。

这一步的破坏性在删除命令上最明显。`rm *.py` 里，`*.py` 由 Shell 展开成一份文件列表，`rm` 拿到的是展开后的结果，它自己既不知道模式长什么样，也没机会确认范围。

#### 示例目录

```text
project/
├── intro.md
├── main.md
├── notes.txt
├── a1.txt
├── a2.txt
└── docs/
    ├── guide.md
    └── deep/
        └── api.md
```

在 `project/` 下执行：

```bash
echo *.md
# intro.md main.md
```

Shell 并没有把 `*.md` 交给 `echo`，而是先替换成两个文件名：

```text
echo *.md  →  echo intro.md main.md
```

`echo` 收到两个参数，用 `printf` 能看出这一点：

```bash
printf '[%s]\n' *.md
# [intro.md]
# [main.md]
```

加引号后不再展开：

```bash
printf '[%s]\n' "*.md"
# [*.md]
```

#### 模式写法

| 模式             | 匹配结果                            | 说明                                                        |
| ---------------- | ----------------------------------- | ----------------------------------------------------------- |
| `*.md`           | `intro.md`、`main.md`               | `*` 不跨 `/`，不进入 `docs/`                                |
| `*.txt`          | `notes.txt`、`a1.txt`、`a2.txt`     | 只匹配当前目录                                              |
| `a?.txt`         | `a1.txt`、`a2.txt`                  | `?` 匹配一个字符                                            |
| `a[12].txt`      | `a1.txt`、`a2.txt`                  | 集合中任选一个                                              |
| `{main,notes}.*` | `main.md`、`notes.txt`              | 先展开为多个模式，再分别 glob                               |
| `docs/**/*.md`   | `docs/guide.md`、`docs/deep/api.md` | `**/` 递归任意层（zsh 默认，bash 需先 `shopt -s globstar`） |

`{a,b}` 的展开先于 glob，属于 brace expansion：它先把一个词变成多个词，每个词之后还可能继续 glob。以 `.` 开头的隐藏文件默认不参与匹配，需要显式写 `.*`。

#### 递归匹配

`**` 沿目录向下匹配，不限制层数。

| shell | 默认                      | 说明                                     |
| ----- | ------------------------- | ---------------------------------------- |
| bash  | `**` 等同 `*`，只匹配一层 | 需要 `shopt -s globstar` 才递归          |
| zsh   | `**/` 默认递归            | `**` 省略 `/` 的写法见 `GLOB_STAR_SHORT` |

```bash
# zsh 默认；bash 需先执行 shopt -s globstar
printf '%s\n' docs/**/*.md
# → docs/guide.md
# → docs/deep/api.md
```

bash 未启用 `globstar` 时，`docs/**/*.md` 与 `docs/*/*.md` 等价，只能匹配 `docs/deep/api.md`。不想依赖 shell 配置时，改用 `find docs -name '*.md'`。

#### 无匹配

bash 把未匹配的模式原样传递：

```bash
printf '[%s]\n' *.nope
# [*.nope]
```

程序收到的是字面量 `*.nope`，不是空列表。zsh 的做法是直接报 `no matches found` 并拒绝执行。

#### 与正则的区别

```bash
ls *.md          # glob，由 Shell 展开
grep '.*\.md'    # 正则，由 grep 解释
```

glob 是 Shell 的路径匹配语言，只有 `*`、`?`、`[]` 这些能力。正则由 `grep`、`sed`、`awk` 等程序自己解释，支持字符类、量词、分组、捕获和锚点。给模式加引号，等于放弃 Shell 展开，把字符串原样交给程序。

两者容易写混，典型错误是：

```bash
# 当前目录存在 a.md、b.md
grep *.md        # 展开为 grep a.md b.md，a.md 被当作模式
```

### 查找程序

Shell 不知道 `ls` 在磁盘上的位置，它按 `$PATH` 查找。`$PATH` 是冒号分隔的目录列表，Shell 依次检查同名可执行文件，找到第一个就执行。

```bash
echo $PATH
which date
which -a sh
/bin/echo $PATH
```

`which` 显示最终选中的路径，`which -a` 列出所有匹配项。`which` 自身也是一个程序，同样位于某个 `$PATH` 目录中。直接写完整路径可以绕过查找，例如 `/bin/echo`。

同名程序出现在多个目录时，排在前面的目录优先，因此 `$PATH` 的顺序会改变实际执行的程序。全都找不到时，Shell 报 `command not found`。

`$PATH` 是环境变量，会被子进程继承。修改它会影响到之后启动的所有程序。

`cd`、`export` 这类命令和 `if`、`while` 等语法不经过 `$PATH`。`echo` 在 bash 中通常也是内建命令，`ls`、`grep` 才是典型的外部程序。

### 创建进程

Shell 本身是一个进程。执行外部命令时，它通过 `fork` 复制出子进程，再由子进程 `exec` 成目标程序：

```text
pid = fork()
if pid == 0:
    execve("/bin/ls", ["ls", "-l"], env)
else:
    wait(pid)
```

`fork()` 返回两次：父进程拿到子进程的 PID，子进程拿到 0。子进程拥有独立的内存副本。`execve()` 用新程序替换子进程的内存映像，PID 保持不变。父进程调用 `wait()` 等待子进程结束，并取得它的返回码，`$?` 就是这个值。

### 有些命令不能交给子进程

`cd` 和 `export` 由 Shell 自己执行，不走 fork 和 exec。这类命令叫内建命令（builtin）。

原因在「当前目录」是进程自己的属性。内核给每个进程记一份工作目录，`fork` 出来的子进程拿到的是副本。假如 `cd` 是个外部程序，Shell 就得开子进程去跑它，子进程改的是自己那份副本，改完退出，副本跟着消失，Shell 的工作目录一点没变。命令看着执行成功了，位置却还停在原地。

`export` 是同一类问题：环境变量也是每个进程一份，交给子进程改，改的只是副本。`if`、`while` 更彻底，它们不是命令，是 Shell 语法，根本没有对应的可执行文件。

判断一条命令是不是内建，用 `type`：

```bash
type cd          # cd is a shell builtin
type ls          # ls is /usr/bin/ls
type -a echo     # 内建和外部两个版本都列出来
```

`type -a` 会列出所有同名版本。`echo` 就是典型例子：bash 优先用内建的那个，`/usr/bin/echo` 一直存在，但很少被调用。

## 打开终端后发生了什么

双击终端图标，看到的是一个窗口。窗口背后有三个程序各管一段：终端模拟器负责显示和输入，Shell 负责解析和执行，内核负责连接两者并提供终端语义。

| 角色       | 例子                   | 负责                       |
| ---------- | ---------------------- | -------------------------- |
| 终端模拟器 | GNOME Terminal、iTerm2 | 绘制字符、接收键盘和粘贴   |
| Shell      | bash、zsh              | 读取命令、解析、执行       |
| 内核       | Linux / macOS          | 提供 PTY、行规程、发送信号 |

终端模拟器和 Shell 之间没有直接连接，中间隔着一对 PTY。

### 文件描述符

每个进程都有三个固定编号的文件描述符（file descriptor，fd），从父进程继承而来：

| fd  | 名称   | 默认指向 |
| --- | ------ | -------- |
| 0   | stdin  | 终端     |
| 1   | stdout | 终端     |
| 2   | stderr | 终端     |

Unix 把普通文件、目录、设备、管道、socket 和 PTY 都当作文件处理。程序不需要知道自己读写的是磁盘、管道还是终端，它只认 fd 编号。

fd 表属于进程。`fork` 后子进程复制一份 fd 表，`exec` 替换程序映像但保留 fd。Shell 只要在 `exec` 之前改掉某个 fd 的指向，接下来的命令就会继承这个设置，重定向和管道都建立在这个机制上。

查看当前 Shell 的 fd：

```bash
ls -l /proc/$$/fd
# 0 → /dev/pts/3
# 1 → /dev/pts/3
# 2 → /dev/pts/3
```

macOS 没有 `/proc` 文件系统，改用：

```bash
lsof -p $$ -a -d 0,1,2
```

### 伪终端

Shell 并不知道自己运行在图形窗口里，它只要求 fd 0/1/2 指向一个终端设备。只有满足这个条件，`isatty(0)` 才返回真，行编辑、回显和 `Ctrl-C` 才会按预期工作。`tty`、`stty` 和作业控制同样依赖终端设备，`vim`、`less` 这类全屏程序也需要通过它接管屏幕。

过去的终端设备是真实硬件。现在由内核提供一对伪终端（pseudo-terminal，PTY）：

| 端     | 使用者       | 内容                           |
| ------ | ------------ | ------------------------------ |
| master | 终端模拟器   | 字节流：键盘输入、待显示的输出 |
| slave  | Shell / 命令 | 终端设备，例如 `/dev/pts/3`    |

从文件的角度看，PTY 就是内核提供的一对设备文件。Shell 的 fd 0/1/2 指向 slave，终端模拟器读写 master。模拟器把字节写入 master，Shell 在 slave 上读到；Shell 把输出写入 slave，模拟器从 master 读出。数据双向流动，与管道相似，区别在于 slave 端附带终端语义：行缓冲、回显、信号和窗口大小。

```bash
tty                          # 当前终端设备，通常为 /dev/pts/N
ps -p $$ -o tty=,comm=       # 当前 Shell 所属终端
```

`tty` 输出的正是 slave 端的设备名。

### 启动链

1. 终端模拟器启动，向内核申请一对 PTY
2. 终端模拟器 `fork` 一个子进程
3. 子进程把 slave 接到自己的 stdin、stdout 和 stderr
4. 子进程 `exec` 成 Shell
5. Shell 向 slave 写入提示符，模拟器从 master 读出并绘制

前 3 步通常由 `forkpty()` 一次完成，`exec` 单独执行。

### 按键如何变成输出

默认处于规范模式。在提示符下输入 `ls` 并按 Enter，经过的路径是：

```text
按下 'l'
  → 模拟器把 'l' 写入 PTY master
  → 行规程缓存并回显 'l'
  → 模拟器读到回显，绘制到屏幕

按下 Enter
  → 行规程把整行交给 Shell
  → Shell 从 PTY slave 读到 "ls\n"
  → Shell 解析命令，fork + exec ls
  → ls 以 slave 作为 stdout，写出文件名
  → 模拟器从 master 读到，渲染到窗口
```

模拟器不解析命令，只转发字节；Shell 不负责字体、颜色和窗口渲染，只读写 slave。规范模式下，按键先由行规程整理成整行，bash 的 readline 还会接管补全和历史记录。

### 行规程

行规程（line discipline）运行在内核的 TTY 驱动里，负责把键盘字节整理成 Shell 可以读取的行。规范模式（canonical mode）下的行为：

| 输入      | 行规程的动作                              |
| --------- | ----------------------------------------- |
| 普通字符  | 写入缓冲区并回显                          |
| Enter     | 把整行交给 Shell                          |
| Backspace | 删除缓冲区最后一个字符                    |
| `Ctrl-C`  | 产生 `SIGINT`，发送给前台进程组           |
| `Ctrl-\`  | 产生 `SIGQUIT`                            |
| `Ctrl-Z`  | 产生 `SIGTSTP`，挂起进程                  |
| `Ctrl-D`  | 不产生信号；空行时表示 EOF，`read` 返回 0 |

全屏程序会切换到 raw 模式，逐字节读取按键并自行重绘屏幕，行为与规范模式完全不同。bash 的 readline 也会切换到自己的模式处理行编辑、补全和历史，但 `Ctrl-C` 这类信号仍然由行规程产生。

```bash
stty -a       # 查看当前行规程设置
stty size     # 终端行列数
```

### 关闭窗口之后

PTY 的生命周期与窗口绑定，窗口关闭时销毁。

master 端关闭后，内核向该终端的前台进程组发送 `SIGHUP`，Shell 及其前台任务通常随之退出。关闭终端后进程仍在运行，一般只有两种情况：

- 进程忽略了 `SIGHUP`，例如通过 `nohup` 启动，或执行过 `disown -h`
- 进程的 PTY 不在这个窗口上，例如 `tmux` / `screen` 的 server 持有自己的 PTY，关闭窗口只断开 client，Shell 仍然挂在 server 的 PTY 上

## 重定向和管道

fd 0/1/2 默认指向终端。重定向让 fd 指向文件，管道让两个进程的 fd 接在同一块内核缓冲区上。两者修改的都是 fd 表，程序本身不需要知道数据去了哪里。

| 写法                    | fd 变化                | 作用                           |
| ----------------------- | ---------------------- | ------------------------------ |
| `ls > files.txt`        | fd1 → `files.txt`      | 标准输出写入文件，已存在则清空 |
| `echo new >> notes.txt` | fd1 → `notes.txt` 末尾 | 标准输出追加                   |
| `wc -l < notes.txt`     | fd0 ← `notes.txt`      | 标准输入从文件读取             |
| `ls /nope 2> err.txt`   | fd2 → `err.txt`        | 标准错误写入文件               |
| `make &> build.log`     | fd1、fd2 → `build.log` | 标准输出和标准错误一起写入文件 |
| `ls \| grep foo`        | 左 fd1 → 右 fd0        | 前一命令的 stdout 接到后一命令 |

### 重定向

以 `cmd > out` 为例，Shell 在 `exec` 之前打开 `out` 并把 fd 1 指向它。`cmd` 不调用 `open`，也不知道输出最终写到了文件。

`/dev/null` 是特殊设备文件，写入的内容直接丢弃。只关心退出状态、不需要任何输出时，写 `cmd > /dev/null 2>&1`。

### 顺序与截断

`2>&1` 表示让 fd 2 指向 fd 1 当前指向的位置。重定向按从左到右的顺序生效，所以位置不同，结果不同：

```bash
cmd > out 2>&1     # fd1 → out，fd2 复制 fd1，两者都写入 out
cmd 2>&1 > out     # fd2 先复制终端，fd1 再指向 out
```

第二条命令中，执行 `2>&1` 时 fd 1 还指向终端，因此 stderr 留在终端，只有 stdout 进入 `out`。

bash 和 zsh 还提供 `&>` 作为简写：`cmd &> log` 等价于 `cmd > log 2>&1`，两个流一起进文件；追加写法是 `cmd &>> log`。

`>` 在命令启动前就截断目标文件。命令随后失败，原内容也无法恢复。`set -C`（`noclobber`）禁止覆盖已有文件，`>|` 可以强制覆盖。

### 持久重定向

`exec` 不带命令时修改的是 Shell 自身的 fd，脚本里常用它临时改变输出方向：

```bash
exec 3>&1              # 把 stdout 复制到 fd 3
exec >log 2>&1         # Shell 的 stdout 和 stderr 写入 log
...
exec >&3 2>&3          # 从 fd 3 恢复
exec 3>&-
```

0/1/2 只是约定，进程可以使用更多 fd。这里借用空闲的 3 保存原来的 stdout，最后再关闭它。

### sudo 与重定向

`sudo cmd > /root/out` 中的 `>` 由当前用户的 Shell 处理，不是由 `sudo` 处理。Shell 先尝试打开 `/root/out`，再启动 `sudo`；普通用户通常没有写权限，`cmd` 还没运行就失败了。

要让 root 处理整条命令，包括重定向：

```bash
sudo sh -c 'cmd > /root/out'
```

`sh -c` 把整段字符串交给 root 的 Shell，`>` 也就由 root 打开。

### 管道

管道把前一命令的 stdout 直接接到后一命令的 stdin。pipe 是内核中的缓冲区，有读写两端，数据单向流动。

```bash
ls | grep foo
```

`ls` 的 stdout 写入 pipe，`grep` 的 stdin 从 pipe 读取。两个命令同时运行，Shell 不会等 `ls` 全部结束再启动 `grep`。

三段命令会建立两个 pipe：

```text
a: fd1 ──▶ pipe1 写端
b: fd0 ◀── pipe1 读端
   fd1 ──▶ pipe2 写端
c: fd0 ◀── pipe2 读端
```

Shell 先建 pipe，再把上一段的 stdout 接到写端、下一段的 stdin 接到读端，然后启动全部命令，自己关闭多余的 fd 并等待结束。

默认只有 fd 1 进入管道，stderr 仍然输出到终端。pipe 有内核缓冲区，Linux 默认 64 KiB，读端消费慢时写端阻塞，形成反压。所有写端关闭后读端才读到 EOF，只要有一个进程没关闭写端，读端就会一直等待。读端提前退出时，写端收到 `SIGPIPE`，默认终止，退出码为 141，`yes | head -n 3` 就属于这种情况。

### 退出状态

`$?` 只记录管道最后一段的返回值：

```bash
false | true
echo "$?"          # 0
```

脚本里因此容易误判：前面某段失败，整体返回值仍然是 0。需要逐段检查时使用 `PIPESTATUS`（bash）或 `pipestatus`（zsh）：

```bash
false | true
printf '%s\n' "${PIPESTATUS[@]}"   # 1 0
```

`PIPESTATUS` 会被下一条命令覆盖，需要先保存：

```bash
false | true
status=("${PIPESTATUS[@]}")
printf '%s\n' "${status[@]}"
```

希望任意一段失败就返回非零，可以启用 `pipefail`：

```bash
set -o pipefail
false | true
echo "$?"          # 1
```

`pipefail` 与 `set -e` 一起使用时，`yes | head -n 1` 会因 `yes` 收到 `SIGPIPE` 而导致脚本退出。`grep` 没有匹配时也返回 1，这类命令应放在 `if` 中，或显式处理返回值。

### 组合使用

`make` 的正常输出走 stdout，错误走 stderr。管道只连接 stdout，`make | grep error` 会漏掉错误信息。把 stderr 并入 stdout 后再接入管道：

```bash
make 2>&1 | tee build.log | grep -i error
```

`2>&1` 让 `make` 的 stderr 指向 stdout 当前的目标，即后面的 pipe。`tee build.log` 把收到的内容写入日志，同时继续向下传递。`grep -i error` 筛选包含 `error` 的行。

位置决定作用对象：

```bash
make 2>&1 | tee build.log   # make 的 stderr 进入管道
make | tee build.log 2>&1   # 2>&1 作用于 tee，make 的 stderr 仍在终端
```

`tee` 默认覆盖日志，`tee -a` 追加。

### 缓冲

这里的缓冲属于程序自身，与 pipe 的内核缓冲区无关。多数程序不会每次写入都立即落盘，而是先写进内存缓冲区：

- stdout 连接终端时，遇到 `\n` 就输出，称为行缓冲
- stdout 连接文件或管道时，攒满缓冲区或程序退出才输出，称为全缓冲
- stderr 通常不缓冲，直接输出

因此程序先向 stdout 写 `out`、再向 stderr 写 `err` 时，`out` 可能仍在缓冲区中，而 `err` 已经写入文件。两个流指向同一个文件时，日志里就可能先出现 `err`：

```bash
cmd > log 2>&1
```

重定向顺序没有问题，差异来自两边的写入时间。

需要日志顺序更接近实际写出顺序时，可以让 stdout 按行刷新：

- `stdbuf -oL cmd`：把使用 stdio 的程序改为行缓冲
- `grep --line-buffered`：让 grep 逐行输出，不积累
- `unbuffer cmd` / `script`：给程序接一个伪终端，使其按行缓冲输出

这些方法让 stdout 更早写出，err 就不会抢在更早写出的 out 前面。多线程或多进程同时写入时，仍然无法保证绝对顺序。

### 课堂案例

统计上次启动以来，sshd 日志里断开连接次数最多的用户。

```bash
ssh myserver 'journalctl -u sshd -b-1 | grep "Disconnected from"' \
  | sed -E 's/.*Disconnected from .* user (.*) [^ ]+ port.*/\1/' \
  | sort | uniq -c \
  | sort -nk1,1 | tail -n10 \
  | awk '{print $2}' | paste -sd,
```

各段职责：

1. `ssh myserver '...'`：在远程主机执行单引号内的命令，结果传回本地
2. `journalctl -u sshd -b-1`：读取 sshd 上次启动的日志
3. `grep "Disconnected from"`：只保留断开连接的记录
4. `sed -E ...`：用捕获组 `(.*)` 提取用户名，替换掉整行
5. `sort`：按用户名排序，使相同用户名相邻
6. `uniq -c`：统计相邻重复行，输出「次数 用户名」，例如 `12 alice`
7. `sort -nk1,1`：按第 1 列数值升序排序，次数少的在前
8. `tail -n10`：取最后 10 行，即次数最多的 10 个用户
9. `awk '{print $2}'`：只保留第二列的用户名
10. `paste -sd,`：把多行合并为一行，以逗号分隔

## bash 编程与脚本

### 返回码

命令成功返回 0，失败返回非 0。`if`、`while`、`&&`、`||` 都依据这个值决定走向。以检查日志中是否存在 ERROR 为例：

```bash
grep -q ERROR app.log
echo $?          # 0 有，1 没有，2 文件无法打开
```

`grep -q` 不输出内容，只返回状态码，因此可以直接配合 `&&` / `||`：

```bash
grep -q ERROR app.log && echo "有错误"
grep -q ERROR app.log || echo "没错误"
```

`&&` 在左侧成功时执行右侧，`||` 在左侧失败时执行右侧。

### 分支

```bash
if grep -q ERROR app.log; then
    echo "app.log 里有 ERROR"
else
    echo "app.log 正常"
fi
```

`if` 后面跟的是命令，不是布尔表达式。命令返回 0 时进入 `then` 分支，`fi` 结束整个判断。

### 循环

逐行读取文件：

```bash
while read -r line; do
    echo "$line"
done < app.log
```

`-r` 保留反斜杠，重定向写在 `done` 之后。`read` 读到 EOF 时返回非 0，循环结束。

遍历一组文件：

```bash
for file in logs/*.log; do
    [ -f "$file" ] || continue
    grep -q ERROR "$file" && echo "$file"
done
```

`for` 遍历列表，`logs/*.log` 由 Shell 预先展开。循环变量加引号，文件名含空格也不会被切开。`for i in $(seq 1 3); do ...; done` 用于执行固定次数。

### 判断

`test` 和 `[` 是同一个命令的两种写法，`[` 在末尾还需要一个 `]`：

```bash
test -f app.log
[ -f app.log ]
```

两种写法都只返回状态码：成立返回 0，不成立返回非 0，可以直接放进 `if`：

```bash
if [ ! -f app.log ]; then
    echo "app.log 不存在"
    exit 1
fi
```

`[` 是命令，不是语法。括号两侧和操作符两侧都需要空格，写成 `[ -f app.log]` 时，`app.log]` 会被当作一个参数，随后报缺少 `]`。

| 判断                 | 写法              |
| -------------------- | ----------------- |
| 文件存在且为普通文件 | `[ -f app.log ]`  |
| 目录存在             | `[ -d logs ]`     |
| 文件可读             | `[ -r app.log ]`  |
| 字符串为空           | `[ -z "$1" ]`     |
| 字符串相等           | `[ "$a" = "$b" ]` |
| 数值比较             | `[ "$n" -lt 10 ]` |

字符串比较用 `=` / `!=`，数值比较用 `-eq` / `-ne` / `-lt` / `-gt`。`[` 中的变量要加引号，否则空值或空格会破坏参数结构。

`[[ ... ]]` 是 bash 语法，不是外部命令，支持 `&&`、`||` 和模式匹配：

```bash
[[ "$line" == *ERROR* ]] && echo "$line"
```

右侧的 `*ERROR*` 是模式，不加引号。`[[ ]]` 只有 bash 和 zsh 支持，需要可移植时仍然使用 `[ ]`。

### 参数

`$0` 是脚本名，`$1` 是第一个参数，`$#` 是参数个数，`$@` 是全部参数。运行 `./check.sh app.log error.log` 时，`$0` 为 `./check.sh`，`$1` 为 `app.log`，`$#` 为 2，`"$@"` 展开为两个文件名。

展开 `"$@"` 必须加引号，否则参数中的空格会被重新切分。

### 示例脚本

脚本只是把命令写进了文件。把前面的规则写进 `check.sh`：

```bash
#!/bin/bash
set -euo pipefail

if [ $# -eq 0 ]; then
    echo "用法: $0 <logfile>"
    exit 1
fi

for file in "$@"; do
    if [ ! -f "$file" ] || [ ! -r "$file" ]; then
        echo "$file 不存在或不可读"
        continue
    fi

    if grep -q ERROR "$file"; then
        echo "$file 有 ERROR"
    else
        echo "$file 正常"
    fi
done
```

第一行的 `#!/bin/bash` 叫 shebang。`#` 在 Shell 里是注释符，但 `#!` 出现在文件开头时是给内核看的：内核读到这两个字节，就知道后面跟的是解释器路径，执行这个文件等于用那个解释器去跑它。`./check.sh` 实际执行的是 `/bin/bash ./check.sh`，所以脚本有没有 `.sh` 后缀不重要，有没有可执行位才重要。

`#!` 后面不查 `$PATH`，写 `#!bash` 找不到程序，得写绝对路径。想让脚本换台机器也能跑，写成 `#!/usr/bin/env bash`，由 `env` 去 `$PATH` 里找 bash。机器上的 bash 只装在 `/usr/local/bin` 时，写死 `#!/bin/bash` 会报 bad interpreter。需要先编译的语言用不了这条路，比如 Java，没有程序能直接接收源码再编译执行。

`set -e` 在命令失败时退出，`-u` 在引用未定义变量时报错，`-o pipefail` 让管道中任意一段失败都判定为失败。`set -e` 不会因为 `if` 或 `while` 条件中的失败而退出。调试时可以加 `set -x`，每条执行的命令都会打印出来。

执行 `chmod +x check.sh` 添加执行权限，然后运行 `./check.sh app.log`。不能只写 `check.sh`，因为当前目录不在 `PATH` 中，`./` 用于明确指定文件。这一限制同时避免当前目录中名为 `ls` 的文件被当作 `ls` 命令执行。

### 权限

`ls -l` 的第一列格式如下：

```text
-rwxr-xr-x  1 user group  1234 Jan 1 12:00 check.sh
```

第 1 个字符表示文件类型，`-` 为普通文件，`d` 为目录。后 9 个字符分为 owner、group、others 三组，每组三个位，依次为读、写、执行，数值是 `r=4`、`w=2`、`x=1`，所以 `755` 对应 `rwxr-xr-x`。

目录的 `x` 表示允许进入，`r` 表示允许列出内容，`w` 表示允许创建或删除其中的文件。脚本缺少 `x` 时，运行会报 permission denied。

修改权限：

- `chmod +x check.sh`：只添加执行位，读写位不变
- `chmod 755 check.sh`：owner 读写执行，group 和 others 读执行

第一列之后的 `1` 是硬链接数，`user` 是 owner，`group` 是所属用户组。普通文件没有额外硬链接时为 1，目录的链接数还会包含 `.` 和子目录。`chmod` 修改权限，`chown user:group file` 修改所有者和用户组。

### 反复运行测试

课堂示例反复运行测试，失败后保留日志：

```bash
#!/bin/bash
set -euo pipefail

stress --cpu 8 &
STRESS_PID=$!

LOGFILE="test_runs_$(date +%s).log"
RUN=1
while cargo test my_test > "$LOGFILE" 2>&1; do
    echo "Run $RUN passed"
    ((RUN++))
done

kill "$STRESS_PID" 2>/dev/null || true
echo "Test failed on run $RUN"
tail -n 20 "$LOGFILE"
```

`&` 把命令放到后台，`$!` 取得它的 PID。`kill` 结束它，`|| true` 避免 `stress` 已经退出时触发 `set -e`。`> "$LOGFILE" 2>&1` 把 stdout 和 stderr 都写进日志，`date +%s` 生成时间戳，避免日志重名。`((RUN++))` 是 bash 的算术自增，等价于 `RUN=$((RUN + 1))`。

`while` 的条件是 `cargo test`：测试通过就继续，失败就退出循环，脚本继续执行末尾的 `tail`。

### shellcheck

bash 的细节较多，脚本写完后可以用 [ShellCheck](https://www.shellcheck.net/) 检查：`shellcheck script.sh`。它会提示未加引号的变量、`[ ]` 写法错误，以及命令替换和管道中的常见问题。逻辑过于复杂的脚本，改用 Python 通常更容易维护。

## 容易混淆的问题

| 问题                                    | 答案                                                                |
| --------------------------------------- | ------------------------------------------------------------------- |
| 终端和 Shell 是同一件事吗？             | 不是，终端是窗口，Shell 是窗口里运行的程序                          |
| `$SHELL` 是当前 Shell 吗？              | 不一定，它是登录 Shell；交互式 Shell 看 `$0`，更可靠的是 `ps -p $$` |
| `$TERM` 是 Shell 类型吗？               | 不是，它描述终端能力，例如 `xterm-256color`                         |
| 终端里必须跑 Shell 吗？                 | 不必，终端只负责启动程序，配置成直接跑 `vim`、`ssh` 也可以          |
| Shell 必须有终端吗？                    | 不需要，脚本、CI、`ssh host 'cmd'` 都可以                           |
| 单引号和双引号相同吗？                  | 不同，单引号按字面处理，双引号会展开变量和命令替换                  |
| glob 和正则相同吗？                     | 不同，glob 由 Shell 展开，正则由 `grep`、`sed` 等程序解释           |
| `cd` 为什么不能是外部程序？             | 子进程无法修改父进程的当前目录                                      |
| `Ctrl-C` 是终端终止进程吗？             | 终端只发送字节，内核行规程产生 `SIGINT` 并发送给前台进程组          |
| 管道两端同时运行吗？                    | 是，Shell 只连接 fd，不缓存整段输出                                 |
| `2>&1` 为什么与顺序有关？               | 它复制 fd 1 当前指向的目标，重定向从左到右执行                      |
| `pipefail` 和 `PIPESTATUS` 有什么区别？ | `pipefail` 修改 `$?`，`PIPESTATUS` 保留每一段的状态                 |
| `if` 是程序吗？                         | 不是，它是 Shell 语法；`[` 才是命令                                 |
| `$?` 和 `$!` 有什么区别？               | `$?` 是上一条命令的返回码，`$!` 是最近一个后台进程的 PID            |
| 为什么脚本要写 `./script.sh`？          | 当前目录不在 `PATH` 中，`./` 用于明确指定文件                       |

## 常用文本工具

这些工具不需要记住全部参数，先了解用途，使用时查阅帮助。

### 帮助系统

```bash
man ls          # 完整手册，q 退出
ls --help       # 常用参数
tldr ls         # 常见示例
```

`man` 是按页组织的完整手册，内容通常包括用法、参数、示例、退出码和作者信息。阅读时按 `/` 搜索，`n` / `N` 跳到下一个 / 上一个匹配。`--help` 输出更短，适合快速确认参数写法；`tldr` 只给常见示例，适合回忆。三种方式都无法解决时，再考虑询问 LLM。

### 工具表

| 命令          | 作用               | 常见写法                                            |
| ------------- | ------------------ | --------------------------------------------------- |
| `cat`         | 打印整个文件       | `cat file`                                          |
| `less`        | 分页查看           | `less file`                                         |
| `head`/`tail` | 文件头 / 尾        | `head -n 20 file` / `tail -n 20 file`               |
| `sort`        | 按行排序           | `sort -n file` / `sort -u file`                     |
| `uniq`        | 去除相邻重复行     | `sort file \| uniq -c`                              |
| `grep`        | 按正则搜索行       | `grep -rn 'TODO' .`                                 |
| `sed`         | 流编辑，常用于替换 | `sed -i 's/old/new/g' file`                         |
| `find`        | 按条件查找文件     | `find ~/Downloads -type f -name '*.zip' -mtime +30` |
| `awk`         | 按列处理文本       | `awk -F, '{print $2}' data.csv`                     |

几个容易忘的点：

- `sort` 默认按字典序，数值排序需要 `-n`
- `uniq` 只去除相邻重复行，先 `sort` 再 `uniq`
- `grep` 的 pattern 是正则，`-r` 递归，`-l` 只输出文件名
- `sed -i` 直接修改文件，`g` 表示一行内全部替换
- `find` 默认递归，`-maxdepth` 需放在其他条件之前；`-size +100M` 按大小筛选
- `awk` 默认按空白分列，`-F,` 改为逗号分隔
