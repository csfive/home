# 容易混淆的问题

这一讲的坑大多不在语法，而在「同一个值被谁拥有、什么时候该重置」。

| 容易混淆                   | 区别                                              |
| -------------------------- | ------------------------------------------------- |
| `wasPressed` / `isDown`    | 本帧按下一次 vs 每帧轮询，跳跃必须用前者          |
| `dy` 赋值 / 累减           | 跳跃是 `dy = -300`，累减会让长按无限加速          |
| 位置乘不乘 `dt`            | 不乘则帧率越高掉得越快，跳跃高度随显示器变化      |
| 取模 / 清零                | 取模留下余数，倒计时与滚动都不漂移                |
| 单根 `Pipe` / `PipePair`   | 一个管一个对象 vs 一对管共用一个 X                |
| `scaleY = -1` / 加高度     | 翻转以绘制点为原点，补 `PIPE_HEIGHT` 才留在原位   |
| `pairs` / `ipairs`         | 遍历所有键（含字符串） vs 只遍历 1..n 的数组      |
| 迭代中 `remove` / 标记后删 | 前者会跳过相邻元素，后者安全                      |
| `init` / `enter`           | 实例化一次 vs 每次切入都跑，参数只能从 `enter` 拿 |
| `scored` / `remove`        | 防止重复计分 vs 推迟删除，两个标记互不相干        |

## 输入与帧

**跳跃会连着触发。** `wasPressed` 读的是「本帧按下的键」集合，集合必须在每帧末尾清空。忘了清空，条件在鸟下落期间一直为真，`dy` 每帧被重置成负数，鸟贴在天花板上抖。

```lua
function love.update(dt)
    gStateMachine:update(dt)
    love.keyboard.keysPressed = {}
    love.mouse.buttonsPressed = {}
end
```

**键盘回调只能有一份。** `love.keypressed` 是全局回调，写在 `Bird.lua` 里也会被覆盖，所以课程用自建表转发。这是 LÖVE 的结构限制，不是 Lua 的限制。

## 表与迭代

**迭代中删除会跳元素。** `pairs` 遍历时删掉当前项，后面的元素整体前移，迭代器接着访问下一个下标，等于跳过了一个。

```lua
-- 倒序删除：下标不受前移影响
for i = #pipes, 1, -1 do
    if pipes[i].remove then
        table.remove(pipes, i)
    end
end
```

**`#t` 只对连续数组可靠。** 表里混了字符串键时 `#` 的结果不保证是最后一个整数下标，`table.insert` 仍然追加到 `#t + 1`，但读的时候别依赖。

## 资源与生命周期

- `love.load` 只跑一次，字体、图片、音源都该在这里建。放进 `init` 会随每次状态重建重复加载，放进 `render` 更糟
- 状态对象是短命的，`change` 每次新建实例，跨局的数据放存档或 `main.lua` 的局部变量
- 同一音源重播会打断自身，想叠音就 `clone()`

## 绘制与缩放

- `push.start` 与 `push.finish` 必须成对，漏掉 `finish` 之后所有绘制都不缩放
- 翻转不是镜像到另一边，`scaleY = -1` 以绘制点为原点，加 `PIPE_HEIGHT` 才填回原位
- 回绕点不等于图片宽，周期小于图片宽时要保证「屏宽 + 周期 ≤ 图片宽」
- 分数别在 `draw` 里改，`render` 只该读取状态
